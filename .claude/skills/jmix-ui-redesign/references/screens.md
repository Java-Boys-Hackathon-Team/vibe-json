## 1. XML или Java

- **XML** - статичный каркас: раскладки, кнопки, поля, тексты из `msg://`.
  Любому элементу можно дать `classNames` и `themeNames`.
- **Java** - всё, что строится из данных: списки карточек, сообщения, бейджи.
  Элементы собираются из `Div`, `Span`, `Image`, `Avatar`, `Button` с CSS-классами.
- В XML есть HTML-элементы (`div`, `span`, `h2`, `nav`, `anchor` с дочерними
  элементами) и компонент `html` с произвольной разметкой:

  ```xml
  <html id="emptyState">
      <content><![CDATA[
  <div class="app-empty"> ... встроенный SVG, заголовок, текст ... </div>
      ]]></content>
  </html>
  ```

  У разметки должен быть один корневой элемент. Подходит для промо-блоков,
  иллюстраций, пустых состояний.
- Атрибуты проверяй по XSD из jar-файла `jmix-flowui`
  (`io/jmix/flowui/view/layout.xsd`, `io/jmix/flowui/menu/menu.xsd`). Пример:

  ```bash
  J=$(find ~/.gradle/caches -name 'jmix-flowui-<версия>.jar' | head -1)
  unzip -p "$J" io/jmix/flowui/view/layout.xsd | grep -n 'name="colspan"'
  ```

## 2. Главный экран

Проверенное решение - узкое меню-рельс:

- ширина около 90 px (`--vaadin-app-layout-drawer-width: 5.75rem`);
- сверху логотип, в середине пункты меню (иконка над короткой подписью),
  внизу переключатель темы, аватар пользователя, кнопка выхода;
- активный пункт: иконка в «таблетке» с фирменным градиентом;
- верхняя панель на широких экранах скрыта, заголовок показывает сам экран:

  ```css
  @media (min-width: 801px) {
    vaadin-app-layout::part(navbar) { display: none; }
  }
  ```

  На узких экранах панель нужна: без неё не открыть выезжающее меню. Там же
  подписи пунктов меню возвращаются в строку.

Детали:

- Иконки пунктов задаются в `menu.xml`: `<item view="..." icon="vaadin:cogs" title="msg://..."/>`.
- Реальная DOM-структура `listMenu` (Jmix 2.5): `ul.jmix-list-menu > li >
  a.jmix-menu-item-link[highlight] > vaadin-icon + span.link-text`. Активный
  пункт помечен атрибутом `highlight`. В другой версии проверь в браузере.
- У кнопки, привязанной к действию (`action="logoutAction"`), текст приходит из
  действия и перекрывает пустой атрибут XML. Убирай его в Java:
  `logoutButton.setText(null)` в `InitEvent`.
- Аватар пользователя - `new Avatar(имя)` с `setTooltipEnabled(true)`, добавляется
  в пустой `div` из XML.

## 3. Экран входа

- Две колонки: слева промо продукта (логотип, бейдж, крупный заголовок с
  градиентным акцентом, 2-3 преимущества карточками, пример результата работы),
  справа карточка с `loginForm`.
- Промо собирается компонентом `html`. Тёмный фон с размытыми цветными «пятнами»
  (`filter: blur(70px)`, медленная анимация) и точечной сеткой смотрится дорого.
- `loginForm` оформляется через `::part(form)` и `::part(form-title)`, выбор языка
  скрывается атрибутом `localesVisible="false"`, если язык один. Заголовок формы
  лучше сделать приветствием, а не названием продукта.
- На узких экранах колонки встают друг под другом, второстепенное скрывается.

## 4. Ключевой экран

Типичная раскладка рабочего экрана: список сущностей слева (сворачиваемый),
рабочая область по центру, панель результата справа. Центр и правую часть разделяй
`split`, чтобы пользователь мог менять ширину.

### Список сущностей

- Карточки вместо `dataGrid`: иконка, заголовок, мета-строка (время, статус).
- Группировка по датам («Сегодня», «Вчера», «Последние 7 дней», «Ранее»),
  поиск по вводу (`valueChangeMode="EAGER"`).
- Меню «…» на карточке: `ContextMenu` с `setOpenOnClick(true)`. Чтобы щелчок по
  меню не открывал карточку:

  ```java
  menuButton.getElement().addEventListener("click", e -> { })
          .addEventData("event.stopPropagation()");
  ```

- Переименование - `dialogs.createInputDialog(...)` с
  `withLabelsPosition(TOP)`, удаление - `createOptionDialog()` с кнопкой
  `ActionVariant.DANGER`.

### Состояния

- **Пусто**: иллюстрация, заголовок, пояснение и 3-4 готовых примера, которые
  подставляются одним щелчком. Лучшая точка входа для нового пользователя.
- **Загрузка**: заглушка на месте будущего результата (анимированные точки,
  «переливающийся» текст), а в списке сущностей пометка «обрабатывается».
- **Ошибка**: карточка с понятным текстом и кнопкой «Повторить», а не только
  всплывающее уведомление.

### Приёмы

- Данные нестандартного экрана грузи через `DataManager` в Java, а не через
  `dataContainer`: проще управлять состоянием. Фильтр по текущему пользователю
  передавай явно, чтобы каждый видел только своё.
- Время выводи в часовом поясе браузера. `Page.retrieveExtendedClientDetails()`
  отдаёт и пояс, и ширину окна: по ширине можно перестроить раскладку для телефона
  (например, `SplitLayout.setOrientation(VERTICAL)`, а список сущностей прятать
  после выбора).
- Markdown из внешних источников (ответы LLM) переводи в HTML на сервере
  (`org.commonmark` с `escapeHtml(true)`, `sanitizeUrls(true)`) и вставляй
  компонентом `Html`, обернув в один корневой `div`.
- Переключатель вкладок проще сделать из двух кнопок в общем контейнере и класса
  `active`, чем через `tabSheet`.
- Копирование и скачивание делаются на клиенте через `executeJs`:
  `navigator.clipboard.writeText($0)` (только HTTPS или localhost) и `Blob` со
  ссылкой `download`.
- Редактор кода или JSON: `codeEditor` с `mode` и `theme` (например, `ONE_DARK`)
  в скруглённой карточке хорошо смотрится и в светлой теме. Для редактирования
  удобнее свой `Dialog`, чем `InputDialog`: большой редактор, кнопка
  «Форматировать», текст ошибки проверки под редактором.
- Карточки версий результата в ленте (например, «Схема обновлена · 7 шагов»)
  с подсветкой той, что сейчас показана, дают историю изменений почти бесплатно.

## 5. Списки и формы

- Контейнеру экрана дай общий класс с отступами, сверху - заголовок и
  подзаголовок страницы (`h2` и `span` из `msg://`), раз верхняя панель скрыта.
- Кнопкам «Создать» и «Сохранить» дай `themeNames="primary"`.
- `formLayout` помести в карточку через `classNames`, длинные поля растяни
  `colspan="2"`, поля JSON замени на `codeEditor`, однострочные значения держи
  в `textField`, а не в высоком `textArea`.
- `genericFilter` требует `box-sizing: border-box; width: 100%`, иначе вылезает
  за край.
- Переведи подписи сущностей и атрибутов в `messages_<язык>.properties`:
  английские названия по умолчанию сильнее всего выдают «админку».
