# Подводные камни и проверка

## Jmix и Vaadin

- Несуществующее имя иконки (`VaadinIcon`) роняет экран при открытии, а не при
  сборке. Проверяй скриптом `scripts/check-icons.sh`. Пример ловушки: `OUTDENT`
  не существует.
- Ошибки в XML-описаниях экранов тоже проявляются только при открытии экрана:
  открой каждый изменённый экран хотя бы раз.
- `ClassList` в Vaadin не умеет `toggle`: используй
  `setClassName(name, !hasClassName(name))`.
- Текст действия перекрывает пустой `text=""` у кнопки в XML, убирай его в Java.
- Если JPQL-запрос выбирает не первую сущность из `from` (join с выборкой другой
  сущности), Jmix может его не понять. Надёжнее переписать запрос от нужной
  сущности через обратную связь.
- `Html` требует ровно один корневой элемент.
- `navigator.clipboard` работает только по HTTPS или на localhost.
- `.gitignore` проектов Jmix бывает с широкими правилами (`themes`, `styles`,
  `index.html`). Проверяй новые файлы: `git check-ignore -v <файл>`.

## Окружение

- `package.json` Vaadin-проектов объявляет `"type": "module"`, поэтому
  вспомогательные Node-скрипты в проекте с `require` должны иметь расширение
  `.cjs`.
- В Playwright вход в Jmix надёжнее делать нажатием Enter в поле пароля: кнопка
  отправки живёт в слоте `submit` формы и её селектор зависит от версии.
- Maven Central может отвечать 429 при первой сборке. Локально помогает зеркало
  в `~/.gradle/init.d/*.gradle` (например,
  `https://maven-central.storage-download.googleapis.com/maven2/`). В репозиторий
  его не коммить.
- Google Fonts может не загружаться за прокси или в закрытом контуре: держи
  запасной системный шрифт в `--lumo-font-family`.
- Сервер может собирать проект другой версией Java: records, pattern matching и
  `Stream.toList()` требуют Java 16+.
- Остановка dev-сервера через `pkill -f bootRun` может убить собственную
  оболочку, если строка команды содержит то же слово. Ищи PID процесса
  приложения по имени главного класса.

## Проверка

1. Локальный запуск с настоящей базой и демо-данными (`./gradlew bootRun`).
2. Скриншоты `scripts/screenshots.cjs`: светлая и тёмная тема, 1440 px и 390 px,
   ключевые сценарии. На что смотреть:
   - переполнения и горизонтальная прокрутка;
   - обрезанные подписи и слишком мелкий масштаб визуализаций;
   - дублирующиеся заголовки (верхняя панель и заголовок экрана);
   - контраст в тёмной теме;
   - пустые, загрузочные и ошибочные состояния.
3. `scripts/check-icons.sh`.
4. `./gradlew test` и production-сборка:
   `./gradlew -Pvaadin.productionMode=true bootJar -x test`, затем
   `java -jar build/libs/*.jar` и повторные скриншоты.
