# Редизайн интерфейса на Jmix FlowUI

Скилл собран по итогам редизайна реального проекта (Jmix 2.5, Vaadin 24.6) и
рассчитан на развитие: после каждого нового проекта дополняй
`references/lessons.md`.

Главная мысль: чтобы Jmix-приложение выглядело как продукт, не нужен отдельный
фронтенд. Хватает трёх уровней работы:

1. **Тема** - дизайн-токены поверх Lumo. Разом меняет все экраны, включая
   стандартные экраны Jmix, и почти ничего не стоит.
2. **Каркас** - главный экран (меню), экран входа, заголовки страниц. Это первое,
   что видит пользователь.
3. **Ключевой экран продукта** - собирается вручную из простых компонентов и CSS.
   Экранам-справочникам хватает темы и мелкой доводки.

Силы вкладывай неравномерно: основной сценарий переделывай полностью, остальное
оформляй темой.

## Порядок работы

### 1. Разведка

- Определи версии Jmix и Vaadin (`build.gradle`), найди тему
  (`src/main/frontend/themes/<имя>/`, класс с `@Theme`), список экранов
  (`view/`, `menu.xml`) и основной сценарий продукта. Прочитай README и код
  ключевого экрана: редизайн часто вскрывает баги в логике, их стоит чинить попутно.
- Проверь `.gitignore`: в проектах Jmix встречаются широкие правила вроде
  `themes` или `styles`, из-за которых новые файлы темы молча не попадут в коммит
  (`git check-ignore -v <файл>`).
- Подними приложение локально с настоящей базой и засей правдоподобные
  демо-данные: заполненные состояния важнее пустых. Сними скриншоты «до»
  (`scripts/screenshots.cjs`).

### 2. Тема

Читай `references/theme.md`, за основу бери `assets/theme-tokens.css`.
Коротко: все цвета, радиусы и тени - переменными на `html`, тёмная схема -
переопределением тех же переменных под `html[theme~="dark"]`, переменные Lumo
переопределяются, чтобы стандартные компоненты подхватили фирменный стиль.
Стили раскладывай по файлам: токены отдельно, каждый экран в `view/<экран>.css`.

### 3. Каркас

Читай `references/screens.md`, разделы «Главный экран» и «Экран входа».
Проверенное решение: узкое меню-рельс с иконками и подписями, верхняя панель
только на узких экранах, экран входа из двух колонок (промо и форма).

### 4. Ключевой экран

Читай `references/screens.md`, раздел «Ключевой экран». Собирай его из `Div`,
`Span`, `Image`, `Avatar` с CSS-классами вместо `dataGrid` и `formLayout`.
Обязательно продумай четыре состояния: пусто, загрузка, данные, ошибка.

Если нужна визуализация, которой нет в Vaadin (диаграмма, граф, схема), пиши
веб-компонент на Lit: `references/components.md` и шаблон
`assets/lit-component-template.js`.

Долгие операции (LLM, внешние API) и поле ввода сообщений:
`references/async-and-input.md`.

### 5. Стандартные экраны

Списки и формы Jmix: общий класс с отступами, заголовок и подзаголовок страницы,
основные кнопки с `themeNames="primary"`, формы в карточках, перевод подписей
сущностей в `messages_<язык>.properties`. Подробнее в `references/screens.md`.

### 6. Проверка

- Открой каждый изменённый экран хотя бы раз: ошибки в XML-описаниях и именах
  иконок Jmix выдаёт только при открытии экрана, а не при сборке.
- Прогони `scripts/check-icons.sh` - он сверяет все использованные иконки
  с `VaadinIcon`.
- Сними скриншоты «после» скриптом `scripts/screenshots.cjs`: светлая и тёмная
  тема, ширина десктопа и телефона, ключевые сценарии (вход, открытие сущности,
  отправка, ошибка, диалоги). Смотри на переполнения, обрезанный текст,
  дублирующиеся заголовки, лишние отступы.
- Собери продовый бандл (`./gradlew -Pvaadin.productionMode=true bootJar`)
  и запусти jar: production-сборка фронтенда отличается от режима разработки.
- Проверь совместимость кода с версией Java на сервере.

Список известных подвохов: `references/pitfalls.md`.

### 7. Пополни журнал уроков

Закончив проект, добавь в `references/lessons.md` то, что оказалось новым:
неожиданное поведение Jmix, удачный приём, ошибку, на которую ушло время.
Если урок общий, перенеси его в соответствующий файл `references/`.

## Принципы

- **Сначала посмотри, потом стилизуй.** DOM стандартных компонентов Jmix
  (меню, фильтры, формы) проще снять из браузера, чем угадывать классы.
- **Схему XML проверяй по XSD** из jar-файла `jmix-flowui`
  (`io/jmix/flowui/view/layout.xsd`, `menu/menu.xsd`): там видно, какие атрибуты
  и вложенные элементы реально поддерживаются.
- **XML - для статичного каркаса, Java - для всего, что строится из данных.**
- **Цвета только через переменные.** Тогда тёмная тема и смена бренда
  получаются бесплатно.
- **Внешние данные не вставляются как HTML.** Markdown из LLM и пользовательский
  текст проходят через рендерер с экранированием.
- **Мелочи решают:** градиент на основной кнопке, мягкие тени, короткие анимации
  появления, точечная сетка на пустых областях, аккуратные пустые состояния.
- **Проверяй глазами.** Скриншоты после каждого заметного шага ловят больше
  проблем, чем чтение кода.

## Структура скилла

| Файл | Когда читать |
|---|---|
| `references/theme.md` | настройка темы, токены, тёмная схема, шрифты |
| `references/screens.md` | главный экран, вход, ключевой экран, списки и формы |
| `references/components.md` | свой веб-компонент на Lit |
| `references/async-and-input.md` | долгие операции, `ui.access`, поле ввода |
| `references/pitfalls.md` | перед проверкой и когда что-то странно не работает |
| `references/lessons.md` | журнал уроков по проектам, пополняется |
| `assets/theme-tokens.css` | стартовый файл токенов темы |
| `assets/lit-component-template.js` | заготовка веб-компонента |
| `scripts/screenshots.cjs` | скриншоты через Playwright |
| `scripts/check-icons.sh` | проверка имён иконок |
