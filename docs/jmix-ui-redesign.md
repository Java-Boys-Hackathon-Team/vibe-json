# Редизайн интерфейса на Jmix: обобщённый опыт

Заметки по итогам редизайна Vibe JSON (Jmix 2.5, Vaadin 24.6). Здесь собраны
подходы, которые переносятся на любой проект на Jmix FlowUI: как устроить тему,
что делать в XML, а что в Java, где упираться в ограничения фреймворка и как
проверять результат.

## 1. Главная идея

Jmix из коробки выглядит как админка. Чтобы интерфейс воспринимался как продукт,
не нужно уходить с Jmix на отдельный фронтенд. Достаточно трёх уровней:

1. **Тема**: дизайн-токены поверх Lumo. Это меняет облик всех стандартных экранов
   сразу и ничего не стоит.
2. **Каркас**: главный экран, экран входа, заголовки страниц. Это первое, что видит
   пользователь.
3. **Ключевой экран продукта**: собирается вручную из простых компонентов и CSS,
   а не из стандартных `dataGrid` и `formLayout`. Экранам-справочникам
   (пользователи, настройки) хватает темы и мелкой доводки.

Силы стоит вкладывать неравномерно: основной сценарий переделывается полностью,
остальное оформляется темой.

## 2. Тема и дизайн-токены

- Тема лежит в `src/main/frontend/themes/<имя>/` и наследует `jmix-lumo`
  (`theme.json`). Стили делятся по файлам: общие токены отдельно, каждый экран
  в `view/<экран>.css`. Все файлы подключаются через `styles.css`.
- Все цвета, радиусы и тени задаются переменными на `html`: свои (`--app-*`)
  плюс переопределённые переменные Lumo (`--lumo-primary-color`,
  `--lumo-base-color`, `--lumo-font-family`, `--lumo-border-radius-*` и т. д.).
  Тогда стандартные компоненты Vaadin сами подхватывают фирменный стиль.
- Тёмная схема задаётся переопределением тех же переменных под
  `html[theme~="dark"]`. В стилях экранов цвета не пишутся напрямую, только
  через переменные: так тёмная тема получается бесплатно.
- Переключение темы делает `ThemeUtils.applyLightTheme()/applyDarkTheme()`, она же
  запоминает выбор. Текущую тему можно узнать из браузера:
  `executeJs("return document.documentElement.getAttribute('theme')")`.
- Внутренности компонентов Vaadin стилизуются через `::part(...)`
  (`vaadin-app-layout::part(navbar)`, `vaadin-login-form-wrapper::part(form)`,
  `vaadin-grid::part(header-cell)`). Список частей есть в документации компонента.
- Шрифты, фавикон и метатеги подключаются в `AppShellConfigurator.configurePage()`
  (`addLink`, `addFavIcon`, `addMetaTag`). В `--lumo-font-family` обязательно
  указывается запасной системный шрифт на случай недоступного CDN.
- Приятный интерфейс держится на мелочах: градиент на основной кнопке, мягкие тени,
  тонкие полосы прокрутки, короткие анимации появления (`fade-up` на 0,3-0,5 с),
  точечная сетка на фоне пустых областей.

## 3. XML или Java

- **XML** хорош для статичного каркаса: раскладки, кнопки, поля, тексты из
  `msg://`. Любому элементу можно дать `classNames` и `themeNames`.
- **Java** нужна для всего, что строится из данных: списки карточек, сообщения,
  бейджи. Такие элементы собираются из `Div`, `Span`, `Image`, `Avatar`,
  им вешаются CSS-классы, и больше ничего не требуется.
- В XML есть HTML-элементы (`div`, `span`, `h2`, `nav`, `anchor` с дочерними
  элементами) и компонент `html` с произвольной разметкой в `<content><![CDATA[...]]>`.
  Через него удобно вставлять декоративные блоки: промо на экране входа,
  иллюстрации пустых состояний, встроенные SVG. У разметки должен быть один
  корневой элемент.
- Прежде чем писать атрибут, стоит проверить его в XSD из jar-файла
  `jmix-flowui` (`io/jmix/flowui/view/layout.xsd`, `menu/menu.xsd`). Там сразу
  видно, что поддерживается: `colspan` у полей формы, `localesVisible` у
  `loginForm`, `theme` у `codeEditor`, `icon` у пунктов меню и т. д.
- Имена иконок нужно сверять с `VaadinIcon`: несуществующее имя (например,
  `OUTDENT`) роняет экран при открытии, а не при сборке.

## 4. Главный экран

- Вместо широкой боковой панели сделана **узкая панель-рельс** (около 90 px):
  иконка раздела и короткая подпись под ней, внизу переключатель темы, аватар и
  выход. Ширина задаётся переменной `--vaadin-app-layout-drawer-width`.
- Верхняя панель (`navbar`) на широких экранах скрыта через `@media` и
  `::part(navbar) { display: none }`, заголовок показывает сам экран. На узких
  экранах верхняя панель возвращается, потому что без неё не открыть меню.
- Стандартное меню (`listMenu`) стилизуется по реальной DOM-структуре
  (`.jmix-menu-item-link`, `.link-text`, атрибут `highlight` у активного пункта).
  Структуру проще всего снять из браузера, чем угадывать.
- Иконки пунктов меню задаются в `menu.xml` атрибутом `icon="vaadin:..."`.
- Текст у кнопки, привязанной к действию (например, выход), убирается в Java
  через `setText(null)` после инициализации: пустой атрибут в XML перекрывается
  текстом действия.

## 5. Экран входа

- Двухколоночная раскладка: слева промо-блок продукта (заголовок, преимущества,
  пример результата), справа карточка с `loginForm`. На узких экранах колонки
  встают друг под другом, второстепенное скрывается.
- Промо собирается компонентом `html`, стили берутся из темы. Декоративные
  анимации (размытые «пятна» на фоне, всплытие карточки) заметно оживляют экран.
- `loginForm` оформляется через `::part(form)` и `::part(form-title)`. Выбор
  языка скрывается (`localesVisible="false"`), если язык один.

## 6. Ключевой экран, собранный вручную

Типичная раскладка рабочего экрана: список сущностей слева, рабочая область по
центру, панель результата справа. Центр и правая часть разделены `split`, чтобы
ширину можно было менять.

Приёмы, которые оправдали себя:

- **Список карточек вместо `dataGrid`**: заголовок, мета-строка, меню «…» через
  `ContextMenu` с `setOpenOnClick(true)`, группировка по датам, поиск по вводу.
  Чтобы щелчок по меню не открывал карточку, событию добавляется
  `addEventData("event.stopPropagation()")`.
- **Пустые состояния** оформляются отдельно: иллюстрация, заголовок, пояснение,
  готовые примеры, которые подставляются одним щелчком. Это лучшая точка входа
  для нового пользователя.
- **Состояние загрузки** показывается там, где появится результат: карточка
  с анимированными точками. Ошибка показывается карточкой с кнопкой «Повторить»,
  а не только всплывающим уведомлением.
- **Вкладки-переключатель** можно сделать из двух кнопок в общем контейнере и
  класса `active`, вместо `tabSheet`.
- **Данные грузятся через `DataManager` в Java**, если экран нестандартный:
  так проще управлять состоянием, чем через `dataContainer` и `loader`.
  Параметр текущего пользователя передаётся явно, чтобы каждый видел только своё.
- **Время** выводится в часовом поясе браузера:
  `Page.retrieveExtendedClientDetails()` отдаёт и пояс, и ширину окна.
  По ширине окна можно переключить раскладку для телефона
  (например, `SplitLayout` в вертикальную ориентацию).
- **Markdown из внешних источников** (ответы LLM) переводится в HTML на сервере
  (`commonmark` с `escapeHtml(true)` и `sanitizeUrls(true)`) и вставляется
  компонентом `Html`. Сырой HTML в таком тексте вставлять нельзя.
- **Копирование и скачивание** делаются на клиенте через `executeJs`:
  `navigator.clipboard.writeText` (работает только по HTTPS или на localhost) и
  `Blob` со ссылкой `download`.
- **Редактор JSON или кода**: `codeEditor` с `mode` и `theme` (например,
  `ONE_DARK`) внутри скруглённой карточки смотрится хорошо и в светлой теме.
  Для редактирования удобнее свой `Dialog`, чем `InputDialog`: полноразмерный
  редактор, кнопка «Форматировать», текст ошибки проверки под редактором.

## 7. Свой веб-компонент

Для визуализаций, которых нет в Vaadin (диаграммы, графы, схемы), удобнее всего
написать веб-компонент на Lit. Lit уже есть в зависимостях Vaadin.

- JS лежит в `src/main/frontend/components/`. Java-обёртка - это класс
  `Component` с `@Tag` и `@JsModule`, данные передаются свойством
  `getElement().setProperty(...)`, например строкой JSON.
- Раскладка и отрисовка выполняются в браузере: серверу не нужно ничего знать
  о геометрии. Удобная схема: рёбра рисуются SVG-слоем, узлы - абсолютно
  позиционированными HTML-блоками (проще стилизовать текст и наведение).
- CSS-переменные темы проникают в shadow DOM, поэтому компонент автоматически
  следует светлой и тёмной теме, если в его стилях используются те же переменные.
- Масштаб «по ширине» считается через `ResizeObserver`, рядом кнопки `+`/`-`.
- После изменения JS нужна пересборка фронтенд-бандла. В режиме разработки
  стили темы подхватываются без перезапуска, а JS-модули нет.

## 8. Асинхронность

- Долгие операции (вызов LLM, внешние API) выполняются в общем пуле потоков,
  объявленном Spring-бином, а не в пуле, который создаёт каждый экран: такие пулы
  не закрываются и копятся.
- Результат сохраняется в базу в фоновом потоке, а интерфейс только отрисовывает
  его через `ui.access(...)`. Иначе ответ теряется, если пользователь закрыл
  вкладку. Для `ui.access` нужен `@Push` на классе приложения.
- В фоне Jmix требует контекст безопасности: `SystemAuthenticator.withUser(...)`.
- Если пользователь может переключиться на другую сущность, пока идёт запрос,
  результат привязывается к той сущности, для которой запрос отправлен, а не к
  выбранной на экране. Отрисовывается он только если она всё ещё открыта,
  иначе показывается уведомление.

## 9. Поле ввода сообщения

- Enter отправляет, Shift+Enter переносит строку:
  `Shortcuts.addShortcutListener(field, handler, Key.ENTER).listenOn(field)`.
  Сочетание с Shift под это правило не попадает.
- Для поля ставится `valueChangeMode="EAGER"`, чтобы значение на сервере было
  актуальным в момент нажатия Enter и чтобы `clear()` гарантированно очищал поле
  в браузере.
- Поле и кнопка отправки оформляются одной «капсулой» с подсветкой при фокусе.
  Под ней уместна короткая подсказка о сочетаниях клавиш.

## 10. Стандартные экраны списков и форм

- Контейнеру экрана даётся общий класс с отступами, сверху - заголовок и
  подзаголовок страницы (`h2` и `span` из `msg://`).
- Кнопке создания и кнопке сохранения даётся `themeNames="primary"`.
- Форма помещается в карточку (`classNames` на `formLayout`), длинные поля
  растягиваются через `colspan`, JSON-поля заменяются на `codeEditor`.
- У `genericFilter` нужно явно задать `box-sizing: border-box` и `width: 100%`,
  иначе с внутренними отступами он вылезает за край.
- Подписи сущностей и атрибутов стоит перевести в `messages_<язык>.properties`:
  английские названия по умолчанию сильнее всего выдают «админку».

## 11. Подводные камни

- `.gitignore` проектов Jmix часто содержит широкие правила (`themes`, `styles`).
  Новые файлы в теме нужно проверить командой `git check-ignore -v`.
- Шаблонные ресурсы (старые спиннеры, картинки, неиспользуемые темы в корневом
  `frontend/`) лучше удалить, чтобы не путаться, какая тема рабочая.
- `ClassList` в Vaadin не умеет `toggle`: используется
  `setClassName(name, !hasClassName(name))`.
- `dataManager.save(a, b)` возвращает `EntitySet`, сохранённые экземпляры берутся
  через `saved.get(a)`. Работать дальше нужно с ними, а не с исходными объектами.
- Если запрос в Jmix выбирает не первую сущность из `from` (join с выборкой
  другой сущности), надёжнее переписать его от нужной сущности через обратную связь.
- Jmix-ошибки в описаниях экранов и иконках проявляются только при открытии
  экрана, поэтому каждый экран нужно открыть хотя бы раз.

## 12. Проверка

- Приложение поднимается локально с настоящей базой, в неё засеиваются
  правдоподобные демо-данные, чтобы увидеть заполненные состояния, а не только пустые.
- Скриншоты снимаются скриптом на Playwright: светлая и тёмная тема, ширина
  десктопа и телефона, ключевые сценарии (вход, открытие сущности, отправка,
  ошибка, диалоги). По скриншотам сразу видны переполнения, обрезанный текст и
  дублирующиеся заголовки.
- Перед деплоем проверяется **продовая сборка** (`-Pvaadin.productionMode=true
  bootJar`) и запускается собранный jar: фронтенд-бандл в production-режиме
  собирается иначе, чем в режиме разработки.
- Код проверяется на совместимость с версией Java на сервере (records, pattern
  matching и `Stream.toList()` требуют Java 16+).

## 13. Короткий чек-лист

1. Токены темы на `html` и `html[theme~="dark"]`, переопределение переменных Lumo.
2. Шрифт, фавикон, метатеги в `configurePage`.
3. Главный экран: компактное меню с иконками, переключатель темы, аватар.
4. Экран входа: промо плюс карточка формы.
5. Ключевой экран: ручная сборка, пустое состояние, загрузка, ошибка с повтором.
6. Уникальная визуализация - своим веб-компонентом на Lit.
7. Долгие операции - общий пул, сохранение в фоне, `ui.access` для отрисовки.
8. Стандартные экраны: заголовки, основные кнопки, карточки форм, перевод подписей.
9. Скриншоты в обеих темах и на узком экране, продовая сборка, запуск jar.
