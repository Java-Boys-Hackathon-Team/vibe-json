## 🖥️ Локальный запуск

Проект самодостаточен: поднимает приложение вместе со своей базой.

```sh
cp .env.example .env     # ключ OpenAI; годится и заглушка
./gradlew -Pvaadin.productionMode=true bootJar -x test
docker compose up -d --build
```

Приложение открывается на `http://localhost:8081`. Панель администрирования базы
поднимается по требованию: `docker compose --profile tools up -d`.

Без `.env` контейнер уйдёт в цикл перезапусков: Spring не сможет подставить
`OPENAI_API_KEY` и упадёт при старте.

## 🏗️ Продовое окружение

На сервере проект **не** поднимает свою базу: она берётся из общей
инфраструктуры (`common-infra`), одной на все проекты.

| Где | Чем запускается | Что поднимается |
|---|---|---|
| Машина разработчика | `docker-compose.yml` | приложение, PostgreSQL, панель администрирования |
| Сервер | `docker-compose.prod.yml` | только приложение, подключённое к сети `common-infra` |

Параметры подключения и токены лежат на сервере в `~/vibe-json/.env.prod`
(права `600`) и в репозиторий не попадают:

```properties
PG_DATASOURCE_URL=jdbc:postgresql://common-postgres:5432/vibejson
PG_NAME=vibejson
PG_PASS=<пароль из add-project.sh>
OPENAI_API_KEY=<ключ или заглушка>
```

Место в общей инфраструктуре заводится один раз:
`~/common-infra/scripts/add-project.sh vibejson`.

## 🚀 Развёртывание

```sh
./deploy.sh main
```

Скрипт забирает ветку, собирает `bootJar` под Java 17, пересобирает образ и
поднимает приложение продовым compose-файлом. Он же проверяет, что рядом есть
`.env.prod` и поднята сеть `common-infra`, - иначе останавливается, ничего не
трогая. То же самое делает workflow `CI/CD Pipeline for Vibe-JSON Project`
(ручной запуск, параметр - имя ветки).

Наружу приложение публикуется обратным прокси сервера:
`./add-domain.sh vibe-json.javaboys.ru http://172.17.0.1:8081`.
